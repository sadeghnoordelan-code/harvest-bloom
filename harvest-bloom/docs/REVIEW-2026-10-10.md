# Harvest Bloom review — 2026-10-10

Reviewed the React components, hooks, catalogue, cart, payment seam, styles, public assets, build configuration and local asset tooling. Reproduced the mobile navigation overlay on https://harvest-bloom.vercel.app/ and confirmed all six deployed product images decode at 729 × 728 pixels. The reported image issue was layout, rather than missing uploads.

## Corrections

- Respect the hidden mobile-navigation attribute; add Escape handling and navigation relationships.
- Bound the focused product image by the available stage dimensions. Use a horizontal arc for stacked layouts and keep arrows separate from product selectors on small screens.
- Disable collection pinning on short screens so purchasing controls remain reachable; retain vertical page scrolling for touch.
- Delay pointer capture until an actual drag, preserving product taps; recover after cancelled gestures and breakpoint changes.
- Load the six small product assets eagerly so products do not appear blank when selected from off screen.
- Initialise saved cart data before persistence; discard invalid and duplicate product identifiers, including inherited object-property names.
- Cancel abandoned video downloads, provide a bounded download timeout, and shorten the hero on video failure.
- Render reduced-motion atmospheric decoration without a continuous animation loop; tolerate an unavailable canvas context.
- Keep contact text within narrow screens and section anchors below the fixed header.
- Remove developer implementation instructions and the false claim that an unpaid order has been submitted from the checkout notice.
- Correct local asset-tool path checks to reject sibling paths that merely share the permitted directory prefix. These routes remain disabled in production and ordinary development.
- Add Vercel configuration for both repository-root and harvest-bloom-root project settings.

## Validation

Production build passed. Unit checks passed for asset-route isolation, write/delete path boundaries, weight limits and invoice arithmetic.

Browser checks passed on Microsoft Edge (Chromium) and Playwright WebKit at 320×568, 390×844, 760×600, 768×1024, 1024×768, 1101×700, 1280×720, 1440×900, 1920×1080 and 844×390. Checked all six product selections, focused-image bounds, reachability of pinned purchasing controls, selector separation, keyboard navigation, dragging, weight changes, totals, cart persistence, checkout notice, cart clearing and horizontal overflow. No page runtime errors or failed local asset responses were recorded.

Additional Chromium checks passed for normal motion, video decode and scroll seeking, touch taps, desktop/mobile breakpoint changes, invalid stored cart recovery and video-download failure. These are 20 viewport/engine cases plus one combined scenario. WebKit on Windows is a browser-engine check, not a test on physical iPhones or Safari hardware.

Dependency vulnerability scanning could not be completed reliably because the npm audit service repeatedly failed with connection resets/timeouts. Do not interpret this as a clean security audit or a guarantee that no bugs exist on every device.

## Run the checks

From harvest-bloom/: npm ci, npm test, npm run build, then npm run preview -- --host 127.0.0.1 --port 4173. In another terminal run npm run test:browser. Set TEST_ENGINES=all to include WebKit and install its browser with npx playwright install webkit. The default Chromium channel is msedge; BROWSER_CHANNEL can select another installed channel. PLAYWRIGHT_MODULE can optionally point at a preinstalled Playwright module. TEST_URL can point at a deployment; the browser checks use isolated storage and do not place or pay for orders. Screenshots and machine-readable results go into the ignored verification directory.
